## Pasos para reproducir

1. Abrir Mis Ingresos y seleccionar Gastos.
2. Agregar gasto con fecha 06/10/2026, concepto `<script>alert(1)</script>`, monto ₡1 y proveedor `QA XSS`.
3. Guardar y observar el mensaje de éxito y la fila resultante.

## Comportamiento actual

Se guardó desde la UI un gasto de prueba por ₡1 con Concepto `<script>alert(1)</script>` y proveedor `QA XSS`. No se ejecutó una alerta JavaScript, pero el listado mostró `Gasto - QA XSS` y no el concepto ingresado como texto; no fue posible verificar que la cadena se persistiera/escapara para mostrarla.

## Comportamiento esperado

Mostrar el concepto como texto inocuo (nunca ejecutar HTML/JavaScript) para poder confirmar el escape de salida.

## Evidencia

Frontend local: mensaje “El gasto ha sido guardado exitosamente”; no apareció diálogo JavaScript; fila resultante `Gasto - QA XSS`. El gasto de prueba de ₡1 permanece en la BD de QA para conservar evidencia y no se eliminó tras expirar la sesión. No se persistió una captura como archivo. ZAP no se ejecutó.

## Estado de verificación

Reproducido durante el ciclo frontend del 06/10/2026.

## Corrección aplicada (15/10/2026)

La operación unificada de creación de gastos ahora transfiere concepto a Descripcion y el servicio persiste ese campo en la entidad Gasto. El listado ya prioriza descripcion, y React lo renderiza como texto, por lo que no ejecuta HTML ni JavaScript.

**Verificación técnica:** la prueba se observó en rojo al exigir que la entidad guardada conservara <script>alert(1)</script> como descripción. La compilación de FiscalHost.Tests y el build del frontend finalizaron correctamente. La reejecución puntual de xUnit no obtuvo veredicto porque vstest.console no logró conectar al proceso testhost tras 90 segundos.

**Estado:** Corregido localmente — pendiente revalidación QA autenticada.
